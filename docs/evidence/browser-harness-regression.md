# Browser queue contamination regression

## Root cause

`browser_extra.mjs` deliberately leaves `sample-amber-after-hours` queued and verifies it survives reload. `browser_verify.mjs` previously reloaded that same tab without clearing its persisted queue. Clicking Play prepends Amber and starts it; appending Saturday therefore produced `[Amber, Saturday]`, not `[Saturday]`.

The first Amber naturally ended, correctly advanced to a second Amber plus its real DJ intro, and only later reached Saturday. The existing 60-second Saturday assertion expired during the second Amber. This is harness state contamination, not a playback attempt token regression or demonstrated background throttling.

## RED evidence

Ran unchanged main successfully, then extra successfully, then unchanged main again. The latter exited 1 at browser_verify.mjs:48 with:

```
Error: Timed out: jukebox.player.current?.id==="sample-saturday-neon"
```

Earlier clean-queue samples showed visible document, unpaused audio, readyState 4, no media error, and approximately two audio seconds per two wall-clock seconds. Saturday appeared normally after the 30-second Amber track.

## Scoped harness correction and GREEN evidence

Before the main playback scenario, click the existing Clear Queue UI and assert `jukebox.player.queue.map(s=>s.id)` is empty. No application code, timeout, playback rate, media seeking, fake events, or service responses changed.

Explicitly seeded Amber via the Queue UI before rerunning the corrected scripts:

```
Contaminated initial queue ["sample-amber-after-hours"]
REUSE_GENERATED=1 node scripts/browser_verify.mjs && node scripts/browser_extra.mjs
```

Combined command exited 0. Both browser exception arrays were empty. Main observed natural speech-to-music and natural music-ended advancement to Saturday in loading phase with queue length 0; skip, mobile overflow, and pause-during-DJ assertions passed. Extra passed real reference MP3 upload, music pause/resume, clear voice, invalid WAV recovery, independent tab queue, and refresh persistence. Exact structured results are in `browser.json` and `browser-extra.json`; screenshots were regenerated by the scripts.

Existing generated tracks were reused; no music generation was requested. The synthetic voice reference was generated by the existing extra script, uploaded for its test, and its temporary files removed by that script.
